## Почему входящие отдельно от CRM-лидов

Текущая CRM требует филиал, имя ученика/клиента, имя контактного лица и телефон. В форме сайта или сообщении VK не всегда есть все поля. Поэтому события сначала попадают в раздел «Входящие обращения». Менеджер отмечает «Не заявка» либо дополняет данные и создаёт CRM-лид. Конвертация использует существующую функцию crm_create_lead с проверкой дубликатов и созданием задачи на контакт.

## Настройка Supabase

1. Проверить и применить миграцию 20261103_crm_inbound_staging.sql.
2. Для Tilda использовать миграцию 20261104_crm_tilda_key_hash_verifier.sql: в приватной таблице хранится только SHA-256 ключа, Edge Function проверяет заголовок через RPC crm_verify_tilda_key. Старый TILDA_WEBHOOK_KEY в Edge secrets больше не используется и подлежит удалению вручную. Для VK нужны VK_CALLBACK_SECRET, VK_GROUP_ID, VK_CONFIRMATION_CODE. Не коммитить и не присылать секреты в чат.
3. Развернуть Edge Function crm-inbound-webhook с verify_jwt=false, потому что Tilda и VK не передают Supabase JWT. Обработчик самостоятельно проверяет секреты. SUPABASE_SERVICE_ROLE_KEY используется только на сервере.
4. Адреса (подставить фактический project ref):
   - Tilda: https://PROJECT_REF.supabase.co/functions/v1/crm-inbound-webhook?source=tilda
   - VK: https://PROJECT_REF.supabase.co/functions/v1/crm-inbound-webhook?source=vk

## Настройка Tilda

1. Настройки сайта → Формы → Webhook.
2. Указать HTTPS-адрес с source=tilda.
3. В параметрах API-ключа выбрать передачу через заголовок. Имя заголовка x-open-stars-webhook-key, значение случайного 256-битного ключа, SHA-256 которого хранится в private.crm_tilda_key_hash.
4. Подключить Webhook только к формам записи через кнопку «Контент» каждого блока → «Сервисы приёма данных». Сохранить, не отключая Tilda CRM/Email. Публиковать только после проверки требований к персональным данным и успешного теста без реальных данных.
5. Отправить тестовую заявку и проверить поля Name, Phone, Comments, tranid, formid. При отличающихся названиях скорректировать сопоставление.
6. Проверить текст согласия на обработку персональных данных, регион хранения данных (текущий Supabase — Сингапур) и требования локализации российских ПДн до публикации.

Инструкция: https://help-ru.tilda.cc/forms/webhook

## Настройка VK

1. Управление сообществом → Callback API.
2. Добавить HTTPS-адрес с source=vk.
3. Указать секретный ключ VK_CALLBACK_SECRET, проверить VK_GROUP_ID.
4. Получить строку подтверждения сервера и сохранить как VK_CONFIRMATION_CODE.
5. Включить message_new, а при наличии — lead_forms_new.
6. Подтвердить сервер, отправить тестовое сообщение и проверить CRM → Продажи → Входящие обращения.

Ограничение: сообщения VK в первой версии приходят как отдельные входящие события, а не как сгруппированные диалоги. Обратная отправка сообщений из CRM пока не реализована.

## Тесты перед активацией

- Tilda: тестовый POST с правильным ключом → 200, с неверным → 401.
- Повтор Tilda tranid → одна запись; отправка без телефона и email → отказ.
- VK: confirmation с правильным секретом и group_id → точный код; неверные данные → 403.
- Повтор VK event_id → одна запись.
- Входящие не появляются у роли marketer; администратор филиала не видит записи без филиала.
- Создание лида без обязательных полей запрещено; конвертация повторно запрещена.
- После конвертации лид появляется в текущей воронке, автоматически создаётся задача.
- Нет записи личных данных и тел webhook в журналы ошибок.

## Ограничения и откат

Нет автоопределения филиала из свободного текста, импорта старых переписок и ответов в соцсети из CRM. Существующая модель CRM в первую очередь рассчитана на учеников; для взрослых направлений нужен отдельный сценарий.

Для отката выключить Webhook в Tilda и Callback API в VK, затем Edge Function. Не удалять таблицу входящих без резервной копии и согласованного срока хранения.
