# Ответы на обращения родителей

## Для сотрудников

1. Откройте «Обратная связь» в кабинете сотрудника.
2. Фильтр «Без ответа» показывает обращения без ответа школы, кроме архивных.
3. Нажмите «Ответить родителю», напишите текст и нажмите «Отправить ответ».
4. Ответ сохраняется под исходным обращением с именем сотрудника и датой. Кнопка «Дополнить ответ» добавляет новую запись в историю.

Директор, управляющий и директор по проектам имеют доступ ко всем округам; администратор — к обращениям своего округа, указанного в обращении. Педагоги, маркетолог, продажник и уволенные сотрудники не получают доступ к этой переписке.

Отправка ответа переводит новое обращение в просмотренное. Закрытие и архивирование остаются отдельными действиями. Удаление тестового обращения удаляет всю его переписку и связанные уведомления; для рабочих обращений используйте архив.

## Для родителей

В меню кабинета и в разделе «Для родителей» есть пункт «Обратная связь». Там видны собственные обращения по выбранному ребёнку и ответы школы. Внизу главного экрана также есть кнопка «Написать школе / посмотреть ответы».

После ответа сотрудника появляется уведомление в колокольчике. При включённых уведомлениях на устройстве ответ также поступает через существующую систему push. Нажатие открывает нужного ребёнка и обращение. Текст личной переписки не выводится на экран блокировки. История обновляется при открытии, возвращении в приложение и каждые 20 секунд, пока раздел открыт; есть кнопка «Обновить».

## Технические гарантии

- `parent_feedback_replies`: неизменяемые ответы с автором, временем и UUID запроса. Запись только через проверенный RPC `staff_reply_parent_feedback`.
- Ответ, смена статуса и уведомление сохраняются одной транзакцией. Повтор того же запроса возвращает прежний ответ без второго уведомления; изменение содержимого при том же UUID отклоняется.
- RLS родительской истории проверяет автора исходного обращения и текущий доступ к ребёнку. Другие родители, в том числе члены той же семьи, чужую переписку не читают.
- Существующие `pp_enqueue`, `pp_deliverable` и `pp_parent` дополнены типом `feedback`; доставка дополнительно проверяет автора обращения и существование конкретного ответа. Worker и ключи push не меняются.
- Миграция: `20260915154339_parent_feedback_staff_replies.sql`.
- Проверка: `supabase/tests/parent_feedback_replies.sql` выполняется с откатом всех сообщений и заданий доставки. Проверяет права, повторы, получателя и переход из уведомления. Тестовые сообщения не отправляются реальным родителям.
