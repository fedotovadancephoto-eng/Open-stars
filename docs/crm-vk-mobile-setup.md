# VK Callback API → CRM OPEN STARS (настройка с телефона)

## Статус

На 2026-11-04 серверный обработчик VK подготовлен, миграции применены, но Callback API сообщества ещё не подтверждён и события не включены. Сайт Tilda уже протестирован отдельно; Instagram не затрагивается.

## Что делает владелец сообщества

1. Открывает vk.com/openstars.school в браузере телефона. При необходимости включает «Версия для компьютера».
2. Управление сообществом → Работа с API → Callback API.
3. Находит **ID сообщества** и **строку подтверждения**, которую VK требует вернуть серверу.
4. Открывает приложение OPEN STARS → CRM → Продажи → «Подключение ВКонтакте» (доступно ролям owner/project_director).
5. Вставляет ID и **строку подтверждения VK** в поля, нажимает «Подготовить подключение».
6. Копирует URL сервера и одноразово показанный секретный ключ из CRM. В настройках Callback API VK добавляет URL сервера и секретный ключ.
7. Подтверждает сервер. При корректной настройке VK получает от нашего обработчика точно ту строку подтверждения, которую показал сам VK.
8. После проверки условий обработки персональных данных включает события «Входящие сообщения» и, если доступно, «Новые заявки из лид-форм». Отправляет тестовое сообщение, проверяет CRM → «Входящие обращения».

Адрес: https://yiwiykbuaggyslfyhlfo.supabase.co/functions/v1/crm-inbound-webhook?source=vk

Важно: секретный ключ Callback API — **не** токен доступа VK. Для приёма Callback API токен доступа не требуется. Не отправлять ключи в чат, не помещать в репозиторий.

## Архитектура и безопасность

- `private.crm_vk_callback_config` хранит group_id, SHA-256 секретного ключа и строку подтверждения VK.
- `crm_vk_generate_setup(group_id, confirmation_code)` доступна только owner/project_director и возвращает ключ однократно; повторная генерация инвалидирует предыдущий ключ.
- `crm_vk_get_setup()` позволяет владельцу восстановить ID и строку подтверждения, но не сам секрет.
- `crm_vk_verify_callback(group_id, secret)` доступна только service_role. Edge Function вызывает её серверным ключом; без верного group_id/секрета событие отклоняется.
- Подтверждение VK возвращает точную строку, выданную VK; не произвольную сгенерированную строку.
- Повторные события с тем же event_id не создают дубли. События сохраняются в `crm_inbound_items`, а не сразу в `crm_leads`.
- Входящие сообщения не становятся CRM-лидами автоматически. Сотрудник квалифицирует обращение.
- Права доступа: anon не может создавать конфигурацию, читать секреты или проверять события.
- Роль marketer не получает доступ к персональным сообщениям.
- Регион текущей Supabase — Сингапур. Перед включением реальных сообщений и данных детей необходимо проверить соответствие требованиям российского законодательства о ПДн, основаниям обработки и локализации. Если требуется первичное хранение в РФ, сначала изменить архитектуру хранения.

## Тесты

- Без конфигурации VK callback отклоняется (403).
- Неверная группа или секрет → 403; верная группа и секрет → разрешено.
- Событие `confirmation` возвращает строку VK, а не JSON.
- `message_new` с валидными полями появляется в «Входящих»; повторный event_id не создаёт дубль.
- `lead_forms_new` проверяется отдельно, если событие доступно в VK.
- Секреты не выводятся в логи, не передаются в URL, не хранятся в открытом виде.
- Для отката отключить Callback API в VK и при необходимости отозвать ключ в CRM (создать новый).

## Ограничения первой версии

Нет отправки ответов из CRM в VK и нет группировки сообщений в диалоги; это сбор и ручная квалификация обращений. В CRM для создания лида нужны телефон, имя ученика, контактное лицо и филиал — при отсутствии данных менеджер уточняет их вручную.
